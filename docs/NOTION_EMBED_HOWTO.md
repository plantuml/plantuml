# Embedding PlantUML Diagrams in Notion Today

Notion doesn't render PlantUML natively yet (see [`NOTION_INTEGRATION.md`](./NOTION_INTEGRATION.md)
for the proposal to fix that properly). In the meantime, you can already put a
live, rendered PlantUML diagram on a Notion page today, using Notion's
built-in `/embed` block and a page PlantUML already publishes. No plugin, no
server, no waiting on anyone.

## TL;DR

1. Open the playground: **https://plantuml.github.io/plantuml/js-plantuml/index.html**
2. Write your diagram.
3. Click the **"Open SVG in a live tab"** button (or the PNG one).
4. Copy the URL of the tab that opens.
5. In Notion, type `/embed`, paste that URL, press enter.

That's it — the diagram renders live inside the Notion page.

## Why this works

The playground's "live preview" button doesn't just take a screenshot — it
opens a small, dedicated page (`preview/index.html` in this repo) whose
entire job is to read a diagram from its own URL and render it, with nothing
else on the page: no editor, no toolbar, just the SVG (or PNG) and a
zoom/pan control. Everything needed to reproduce the diagram — the full
PlantUML source — is packed into the URL itself, compressed and encoded
with the same scheme PlantUML's official server has used for years
(`plantuml-codec.js` in this repo). There is no backend involved: opening
that URL anywhere just runs `plantuml.js` in the browser and renders.

That also means it's a plain, ordinary web page with no restriction on being
loaded inside a frame — which is exactly what Notion's `/embed` block does
under the hood (it puts the URL you give it in an iframe). This isn't
theoretical: it was verified by loading the preview URL inside a real
cross-origin iframe and confirming it renders with no `X-Frame-Options` or
CSP block getting in the way. Notion's `/embed` will do the same thing.

## SVG or PNG?

Both live tab buttons work the same way; pick whichever `format` suits how
you'll use the embed:

- **SVG** (`?format=svg`) — sharp at any zoom level, smaller URL. The
  default choice for most diagrams.
- **PNG** (`?format=png`) — a rasterized bitmap. Useful if you specifically
  need a PNG (some downstream tools handle SVG embeds inconsistently).

## Dark or light?

The preview URL takes a `theme` parameter (`?theme=light` or `?theme=dark`)
that controls the diagram's own colors — set it by toggling dark mode in
the playground before opening the live preview, or by editing the URL
directly. It does **not** automatically follow Notion's own light/dark
setting: the embed is a separate origin with no channel back to Notion to
know which theme is active, so pick the one that matches your page (or
matches most often) and accept that a theme switch on the Notion side won't
update it.

## Limitations worth knowing before you rely on this

- **Editing means re-embedding.** The diagram's source lives in the URL, so
  changing the diagram produces a *different* URL. Notion's embed keeps
  pointing at the old one until you delete it and `/embed` the new URL —
  there's no in-place refresh. Fine for a diagram that's mostly stable;
  friction for one your team edits often.
- **Resizing is manual.** Notion doesn't ask the embed how tall it wants to
  be, so you'll drag the block's resize handles yourself. The preview
  page's zoom/pan control (bottom of the embed) helps you fit a large
  diagram into a small block without it looking cut off.
- **The source is not private.** Anyone with the embed URL can decode the
  full PlantUML source from it (it's compressed, not encrypted) — the same
  as any link generated by PlantUML's public server. Don't use it for
  diagrams containing anything sensitive.
- **Requires the viewer to reach `plantuml.github.io`.** Unlike a true
  native integration, this needs network access to load each time; it
  won't render for someone fully offline.

## This is a stopgap

This gets a real diagram onto a real Notion page today, which is worth
doing on its own. But it's still an external iframe, not a first-class
Notion block — no in-place editing, no auto-resize, no offline support, and
Notion doesn't know a "diagram" lives there at all. That's exactly the gap
[`NOTION_INTEGRATION.md`](./NOTION_INTEGRATION.md) proposes closing
natively. If you're using this workaround for real work, that's useful
evidence for that proposal — mention it if you ever get the chance to raise
this with Notion.
